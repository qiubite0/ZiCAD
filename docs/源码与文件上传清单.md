# ZiCAD 源码与文件上传清单

## 先确定“上传”的对象

1. **GitHub/Gitee 源码仓库**：上传可编译、可运行、可测试的源码和说明。
2. **版本发布附件**：另放编译好的网页、原生程序、校验值与版本说明。
3. **服务器部署**：除静态网页，还需要转换程序、后台服务与生产配置。

这三类文件不能混为一谈。只上传 `dist/web/` 可以发布静态界面，但不会自动获得 AI 转发、DWG 转换、登录或文件存储服务。

## 完整源码仓库：必需上传

| 路径 | 内容和原因 |
|---|---|
| `Cargo.toml`、`Cargo.lock` | 工作区和锁定依赖，保证版本可复现 |
| `.cargo/config.toml` | 工作区支持的构建/xtask 别名 |
| `rustfmt.toml`、`clippy.toml` | 代码规范 |
| `apps/cadcraft-web/` | 网页入口、HTML、Trunk、文件上传下载和宿主桥 |
| `apps/cadcraft/` | 原生程序入口与平台集成 |
| `apps/cadcraft-cli/` | 本地转换器及 MCP 命令行入口 |
| `crates/` 全部工作区成员 | 几何、绘图数据、命令、渲染、文件、UI、MCP；不能只传新增 UI 文件 |
| `xtask/` | 资产、分层、构建和检查工具 |
| `tools/dev-proxy.py` | 已整理进仓库的静态/AI 转发/DWG 转换开发服务 |
| `tools/run-local.ps1` | Windows 本地启动辅助脚本 |
| `tools/test_dwg_conversion.py` | HTTP 转换和真实 DWG 读回测试 |
| `tools/gen_mep_dxf.py`、`tools/requirements-demo.txt` | 可选演示图生成器与依赖声明 |
| `README.md`、`docs/` | 项目定位、功能边界、运行说明、二开来源和协议 |
| `LICENSE-MIT`、`LICENSE-APACHE`、`NOTICE`、`ATTRIBUTION.md` | 上游版权、许可和素材记录 |
| `contributors/` | 原有贡献者信息，不把上游成果改写成本项目独立原创 |
| `assets/`、`examples/` | 编译/演示所需的原有开放素材与示例 |
| `crates/ui-egui/assets/fonts/` | 网页中文 UI 字体及附带许可/来源说明 |
| `.gitignore` | 排除凭据、缓存、日志和发布产物 |

`packaging/` 可随完整源码保留；若准备发布桌面安装包，还应单独核对品牌图案、签名、应用 ID 和升级策略。上游 `.github/workflows/` 不是运行源码的必要部分，首次推送前应按自有仓库调整；交付包默认不启用这些工作流。

## 演示文件

建议包含已确认可公开的合成图纸：

- `apps/cadcraft-web/dev-host/apartment.dxf`：上游示例拷贝。
- `mep-coordination.dxf`、`mep-coordination-en.dxf`：本地合成管综平面演示。
- 可另附 ZiCAD 自身截图，避免截图中出现密钥、个人聊天或其他软件窗口。

不要把真实客户施工图、内部项目图纸、带私人属性的文件作为公开测试集。需要真实工程验证时，单独准备有授权并脱敏的样本。

## 不应上传到公开源码仓库

- `target/`、`.git/`、编译中间文件、Python `__pycache__/`。
- `dist/`：除非专门用于静态发布，源码仓库通常不收录。
- `.env`、真实 API Key、浏览器导出配置、账户 token、Cookie、私钥和签名证书。
- 当前仓库外的 `test-llmi.ps1`：含个人测试凭据，**明确不放入上传包**。
- 原始 `PHASE0.md`、代理日志、抓包、个人路径和私人开发记录。
- `output/` 的临时产物、Downloads 文件、模型缓存、字体下载缓存。
- 上游 ArtCraft 商标图案；纯文字来源说明和许可证继续保留。
- 未调整的自动发布工作流和签名配置。

## 运行包与部署包：另行准备

### 网页运行包

`dist/web/` 中的 HTML、JS、WASM、宿主页和公开示例图。必须由对应源码版本重建，不混用旧 WASM 与新页面。

### 本地完整运行包

网页运行包 + `cadcraft-cli` 对应平台程序 + 开发服务 + Python 运行环境说明 + 许可证和启动说明。源码压缩包不会包含你本机的 Python、Rust 或 `target/`。

### 正式网站部署

需要另外实现或配置身份认证、权限、限流、HTTPS、凭据管理、任务资源限制和文件隔离。目前开发代理允许自定义模型地址转发，不能原样当作公开生产 API 上线。

## 推荐首次上传目录

```text
ZiCAD/
├── README.md
├── Cargo.toml / Cargo.lock
├── LICENSE-MIT / LICENSE-APACHE / NOTICE / ATTRIBUTION.md
├── .cargo/ / .gitignore
├── apps/
├── crates/
├── xtask/
├── tools/
├── examples/ / assets/
├── docs/
├── contributors/
└── packaging/                 # 发布桌面版前继续审核
```

仓库内目录和可执行文件保留部分 `cadcraft` 名称属于兼容实现，不代表用户看到的产品名未改。不要在首次上传前再次全局替换目录、crate 和协议标识。

上传包附带 `UPLOAD-MANIFEST.csv`，逐文件列出路径、大小和 SHA-256；`PACKAGE-REPORT.md` 列出排除项、扫描结果和未完成审核事项。
